# Valigia — WardApp 0.5.0 + Hubitat 0.12.1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WardApp prepara la valigia di un viaggio di Hubitat con i capi veri dell'armadio; Hubitat la mostra e la fa spuntare nella scheda Valigia del viaggio.

**Architecture:** In WardApp una funzione pura `packTrip` (outfit per attività con `ruleOutfits`, riuso, bucato, essenziali, addosso in partenza, capienza, consigli) e un modulo `packs.js` che salva la lista e le scelte manuali; API della suite col segreto condiviso. In Hubitat `trips/pack.js` fa da ponte (manda i dati del viaggio, tiene in cache l'ultima lista) e la scheda Valigia la mostra.

**Tech Stack:** come prima (Node 24, Fastify 5, node:sqlite, React 19 + Vite + TS).

**Spec:** `docs/superpowers/specs/2026-10-06-viaggi-design.md` §9 (più §7 per il promemoria della sera prima, §8 per `weather_changed`).

## Global Constraints

- Repo e branch: WardApp `wardapp-0.5.0` (da `wardapp-0.4.0`), Calendary `hubitat-0.12.1` (da `hubitat-0.12.0`). Versioni: WardApp `0.5.0`, Hubitat `0.12.1`.
- Nessuna chiamata reale (AI, WardApp, Open-Meteo finti nei test).
- Etichette delle attività uguali a Hubitat: beach, hiking, dinner, work, sport, city, party, other. Bagagli: backpack_s 14, backpack_l 24, cabin 32, suitcase 60 punti di ingombro (`bulk × quantità`).
- Categoria predefinita per etichetta (id delle categorie di WardApp, con ripiego sulla categoria la cui fascia contiene la formalità indicata, altrimenti la più vicina): beach→casual (2), hiking→streetwear (1), dinner→elegant (5), work→everyday (3), sport→streetwear (1), city→everyday (2), party→night_out (4), other→everyday (2). Modificabile in WardApp (impostazione `pack_tag_categories`).
- Testi per l'utente in italiano.

## Review Focus

1. Armadio quasi vuoto (nessuna scarpa, nessun capo per una categoria) → lista comunque prodotta, con avviso, senza eccezioni. Test in Task 1.
2. Viaggio di un giorno e viaggio di 21 giorni con bucato → quantità sensate (niente 22 paia di calze). Test in Task 1.
3. Rigenerare dopo aver tolto un capo, aggiunto un capo e spuntato alcuni → scelte conservate; un capo venduto nel frattempo sparisce. Test in Task 3.
4. WardApp spento o token errato → Hubitat mostra l'ultima lista in sola lettura con avviso, mai un errore bianco. Test in Task 5.
5. Capo con `quantity` 3 (tre t-shirt uguali) → conta come tre ricambi, non tre righe. Test in Task 1.

### Task 1: motore della valigia — outfit, riuso, essenziali, addosso

**Repo:** WardApp. **Files:** Create `wardapp/server/src/pack.js`; Test `wardapp/server/test/pack.test.js`.

**Interfaces:**
- Produces: `packTrip(input) → Pack` (pura, nessun accesso al DB).
  - `input = { trip: { startDate, endDate, bag, canWash, departsInDays, days: [{ date, tags: string[], weather: { min, max, rainy } | null }] }, items: Item[] /* attivi, viste di items.js */, categories: Category[], tagCategories: Record<tag, categoryId>, removed: string[], added: string[], capacities?: Record<bag, number> }`
  - `Pack = { lines: Line[], worn: string[] /* itemId addosso in partenza */, capacity: { used, max, fits, suggestBag: bag|null }, tips: string[], warnings: string[] }`
  - `Line = { key /* itemId oppure 'todo:<kind>' */, itemId: string|null, name, group: 'top'|'bottom'|'dress'|'outerwear'|'shoes'|'underwear'|'swim'|'accessory'|'essential', qty, reasons: string[], worn: boolean, manual: boolean, dirty: boolean, bulk }`
- Esporta anche `DEFAULT_TAG_CATEGORIES`, `TAG_FORMALITY`, `CAPACITY`, `resolveCategory(tag, categories, tagCategories)`.

- [ ] **Step 1: Test** `pack.test.js` (oggetti item costruiti a mano: `{ id, name, category, type, colors, pattern, formality, warmth, waterproof, seasons, bulk, quantity, dirty, status:'active', washAfterEffective }`):
  - `outfit per attività con riuso`: 4 giorni, tag `city` ×4, armadio 3 top, 2 bottom, 2 scarpe → le righe top+bottom sono al massimo 4 e ogni riga ha `reasons` che contiene `'🏙️ Città'`.
  - `cena elegante usa la categoria elegante`: un giorno `dinner` → in lista il capo con formalità 5 (camicia/blazer), non quello da 1.
  - `riuso con wash_after`: 6 giorni città, una t-shirt `washAfterEffective 1, quantity 3` + jeans `washAfterEffective 6` → la t-shirt ha `qty` 3 (non tre righe), i jeans `qty` 1.
  - `bucato limita a 4 giorni`: 21 giorni, `canWash: true` → riga intimo `qty` 5 (4 + 1 di scorta), calze 5; senza bucato 22.
  - `essenziali`: 4 giorni con 3 di mare e uno piovoso con minima 9° → costume `qty` 2 (1 ogni 2 giorni di mare, max 3), righe `todo:towel` "Telo mare", `todo:slippers` se l'armadio non ha ciabatte, ombrello o capo `waterproof`, un capospalla con `warmth ≥ 3`, pigiama 1. Senza capi d'intimo nell'armadio → righe `todo:underwear` e `todo:socks` con le quantità.
  - `gita di un giorno`: intimo `qty` 1 (nessuna scorta), niente pigiama.
  - `addosso in partenza`: il capospalla e le scarpe più ingombranti hanno `worn: true` e `worn` contiene i loro id.
  - `capi sporchi`: un capo `dirty` vale se `departsInDays > 3` (con `dirty: true` e consiglio "lavalo prima di partire"), altrimenti no.
  - `armadio povero`: nessuna scarpa → `warnings` contiene il testo di `missingFor` per la categoria e nessuna eccezione.
  - `removed/added`: un id in `removed` non compare mai; un id in `added` compare con `manual: true` e `reasons` `['aggiunto da te']`.
- [ ] **Step 2: Run** `cd wardapp/server && node --test test/pack.test.js` → FAIL (modulo assente).
- [ ] **Step 3: Implement.** Occasioni: per ogni giorno i suoi tag (senza tag = `city`); per tag: giorni, meteo peggiore (min dei minimi, max dei massimi, pioggia se un giorno è piovoso → `rainProb` 80) come `summary` per `ruleOutfits({ category, items, summary, season: seasonOf(startDate), count: min(giorni, 4), recentIds })` dove `recentIds` = capi utilizzabili non ancora scelti (così i capi già scelti prendono il bonus e vengono riusati). Giorni di un capo = occasioni in cui è usato (outfit assegnati a rotazione). Copie = `ceil(giorniEffettivi / max(1, washAfterEffective))` con `giorniEffettivi = canWash ? min(giorni, 4) : giorni` (`washAfterEffective 0` = 1 copia); `qty = min(copie, quantity)`, la differenza con altri capi dello stesso ruolo e fascia, altrimenti avviso "Ti servono N <ruolo> in più". Essenziali con `type` di `underwear_swim` (`/boxer|slip|mutand|intimo|reggiseno/`, `/calz/`, `/pigiam/`, `/costum/`) e di `accessory`/`shoes` (`/ombrell/`, `/ciabatt/`, `/trekking|scarpon/`). Addosso: per ruolo `outerwear`, `shoes` e `top` con `warmth ≥ 4`, il capo con `bulk` più alto.

### Task 3: liste salvate, AI e API della suite

**Repo:** WardApp. **Files:** Create `wardapp/server/src/packs.js`, `wardapp/server/src/pack-routes.js`; Modify `wardapp/server/src/auth.js` (rotte suite col token), `wardapp/server/src/app.js` (registrazione), `wardapp/server/src/db.js` (tabella); Test `wardapp/server/test/packs.test.js`.

**Interfaces:**
- Table `trip_packs (trip_id PK, profile_id, trip TEXT JSON, result TEXT JSON, checked TEXT JSON '[]', added TEXT JSON '[]', removed TEXT JSON '[]', ai INTEGER, generated_at, updated_at)`.
- `packs.js`: `generatePack(tripId, trip) → PackView` (async; usa `packTrip`, poi, se `aiEnabled()`, una chiamata `complete` che restituisce JSON `{ tips: string[], swaps: [{ out, in }] }`: al massimo 3 scambi accettati solo se `in` è un capo attivo dello stesso ruolo, non già in lista, non rimosso, con formalità entro ±1; consigli dell'AI al posto di quelli a regole se almeno uno; se l'AI fallisce restano le regole), `getPack(tripId) → PackView` (404 "Valigia non ancora preparata"), `markItem(tripId, key, { checked?, removed? })`, `addItem(tripId, itemId)`, `returnPack(tripId, itemIds) → { count }` (usa `putInLaundry`), `deletePack(tripId)`, `searchItems(q) → [{ id, name, category, thumbUrl }]`, `getTagCategories()/setTagCategories(map)`.
- `PackView = Pack & { tripId, generatedAt, checked: string[], counts: { total, checked }, lines: (Line & { checked: boolean, thumbUrl: string|null })[] }`; `thumbUrl` firmato come in `/suite/today`. Capi non più attivi (venduti, eliminati) spariscono dalle righe alla lettura, con avviso "Alcuni capi non sono più nell'armadio: rigenera".
- Rotte (sotto `/api`): `PUT /suite/packs/:tripId` (body = `trip` del Task 1 senza `items`), `GET /suite/packs/:tripId`, `PATCH /suite/packs/:tripId/items/:key` (`{ checked?: boolean, removed?: true }`), `POST /suite/packs/:tripId/items` (`{ itemId }`), `POST /suite/packs/:tripId/return` (`{ itemIds }`), `DELETE /suite/packs/:tripId`, `GET /suite/items?q=`; per la webapp di WardApp `GET/PUT /pack/tags`. Le rotte `/api/suite/packs…` e `/api/suite/items` accettano il Bearer della suite (come `/api/suite/today`).

  - `spunta, togli, aggiungi, rigenera`: spunto un capo, ne tolgo un altro, ne aggiungo un terzo; `PUT` di nuovo → spunta conservata (se il capo è ancora in lista), tolto assente, aggiunto presente con `manual`.

  - `DELETE` → poi `GET` 404.
